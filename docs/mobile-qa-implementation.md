## Additional bugs found

- Expo's native token promise survived a rejection, making registration retries fail until reload. The SDK patch and an actual SDK regression test address this. [Expo changelog](https://github.com/expo/expo/blob/sdk-57/packages/expo-notifications/CHANGELOG.md)
- Registration was marked successful before the backend accepted it; lost responses also needed opt-out cleanup.
- Shared-bottle start recovery revalidated an expired original end time, and could restore/reset bottle setup. The replacement RPC returns an existing night's current snapshot without changing inventory, plans or ended status.
- Mutable bottle form payloads could reuse an earlier request key after an uncertain failure. Those requests now retain their original payload.
- A known rejected start could leave its persisted setup behind. Successful setup cleanup now has a completion marker, and rejected starts clear recovery state.
- Offline saved drinks were missing from immediate counts/plan progress, and pending entries could become unreachable when their night failed to load.
- Blank/zero-strength custom-drink guidance conflicted with the shared domain validation. Alcohol-free drinks use the existing chaser path.
- Warning dismissal could leave an empty enclosing card; some labels still referred to the old Account/History tab names.
- Browser validation found missing JSON import attributes, outdated consent/breakdown selectors, ambiguous Not now selectors, and an account-deletion fixture missing the current Apple revocation dependency. Fixtures now verify the current interactions and real revocation gate for email accounts.
- Browser traces also revealed the web tour stealing focus after a dialog closed, and Safari losing a sign-out tap when the account menu blurred. Both are fixed in their shared components; an open account menu also places keyboard focus on its first action consistently.
- Safari reported a background notification fetch during a page reload. Inbox polling now suspends and cancels requests on page exit, visibility loss and offline transitions, including page-cache restoration.
- Tour tests continue checking for real night/entry/photo writes while allowing the separate default-country preference save and the identified account block-list read. Consent, group breakdown, renamed-member and recap selectors now describe the current UI.
- Photo failure injection now remains active until the user selects Retry, with an assertion that it actually ran. Upload tests block the PWA service worker so it cannot bypass request interception. [Playwright network guide](https://playwright.dev/docs/network)

### Material interaction decisions

- Settings and Entries use the existing routes. The Entries tab retains completed-night recaps and adds access to locally saved entries.
- Tours are considered seen on first display, matching the web, so closing/backing out does not cause another startup tour. Invitations/deep links take priority.
- Entries defaults closed; the main logging controls stay prominent. Ordinary drink logging is one tap with a short accidental-tap guard and existing undo.
- Unsubmitted setup is temporary. A submitted request with an unknown result is a recoverable operation, not an editable saved draft.
- Shared bottle inventory remains online-only; normal drink entries retain offline support. Invite sharing works offline once its link is ready, while replacement/revocation waits for internet.
