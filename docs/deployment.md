## Hosted authentication

Hosted Auth uses the production Site URL and allows these callback destinations:

- `https://drink-with-desire.vercel.app/auth/confirm?**`
- `https://dwd-*-ariyoxs-projects.vercel.app/auth/confirm?**`
- `http://localhost:3000/auth/confirm?**`
- `http://127.0.0.1:3000/auth/confirm?**`

Email confirmation, secure password changes, refresh-token rotation, and the existing TOTP MFA capability are enabled. Passwords require at least eight characters. Anonymous sign-in is disabled. See [Supabase redirect URL rules](https://supabase.com/docs/guides/auth/redirect-urls).

The separate production file is `supabase/hosted/supabase/config.toml`. Invoke the Supabase CLI directly from `supabase/hosted` to review its diff:

```sh
supabase config push --project-ref kdplbebaotvgcvjggacz
```

Inspect the displayed diff before accepting. Running `npm exec` in this nested directory can run from the npm workspace root and select the local config. Do not push `supabase/config.toml` to production: its URLs and email settings are for local Docker development. The hosted config was applied and verified with no remaining API, database, Auth, or Storage differences.

**Email delivery is deferred by the user.** Supabase's default email service restricts recipients. Configure custom SMTP with a verified sender before public registration. [Supabase SMTP documentation](https://supabase.com/docs/guides/auth/auth-smtp).

After SMTP setup, install the confirmation and recovery HTML from `supabase/templates`. These templates preserve invitations and support confirmation on another device. The default PKCE email flow depends on opening the email in the browser that requested it. New free projects restrict email-template customization with the default provider. [Supabase email-template change](https://supabase.com/changelog/46599-changes-to-email-template-customisation-on-free-tier).

The security advisor flags callable SECURITY DEFINER RPCs. These intentional transaction boundaries use empty search paths and explicit host/member authorization; the lifecycle suite exercises forbidden access. Anonymous invite previews expose limited information for a hashed bearer token. Audit and raw invite tables intentionally have no browser grants or policies. See [database access advisories](https://supabase.com/docs/guides/database/database-linter) and [RLS with no policy](https://supabase.com/docs/guides/database/database-linter?lint=0008_rls_enabled_no_policy).

The performance advisor reports five foreign keys without covering indexes and unused indexes on the new database. Review these as data grows; do not drop indexes just because the database is empty. [Foreign-key index advisory](https://supabase.com/docs/guides/database/database-linter?lint=0001_unindexed_foreign_keys).

Invite throttling remains per process. A durable limiter or Vercel Firewall rule is still needed for a broad public launch.
